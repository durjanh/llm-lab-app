Lab 11 · Routing

Pay for correct answers, not requests

You can send every task to a large model, send every task to a small one, try the small one first and escalate, or let a router decide up front. This calculator compares the four on what decides the choice: cost per correct answer, accuracy and latency.

Prices are Anthropic list prices as of October 2026. Check the pricing page before relying on them. Accuracy and latency values are illustrative placeholders. Measure your own with an eval on your real tasks, because the answer depends almost entirely on them.

2. Your workload and the two mixed strategies

The share of hard tasks decides how much a mixed strategy can save. A cascade lives or dies by its check. A router pays its cost on every task, and each routing mistake costs either money or accuracy.

4. How the numbers are worked out

  • Cost per call is input tokens times the input price, plus output tokens times the output price, with prices per million tokens.
  • Accuracy of one model is the easy share times its easy accuracy, plus the hard share times its hard accuracy.
  • Cascade. Every task pays for the small model and the check. The check escalates a wrong answer at the catch rate, and a correct answer at the false escalation rate. Escalated tasks also pay for the large model and take its answer.
  • Router. Every task pays for the router. It sends a hard task to the large model, and an easy task to the small one, with a probability equal to the routing accuracy. Its mistakes go the other way.
  • Cost per correct answer is cost per task divided by accuracy. Monthly cost is cost per task times tasks per month.
  • Assumptions. Within a task type, the two models make mistakes independently. The check and the router are equally good on easy and hard tasks. Caching, retries and rate limits are not modelled.

Engineering takeaways

  • Judge cost per completed task, not per request. A cheaper request that needs retries is not cheaper. Compare strategies on what you pay for each answer you can use.
  • Before building a cascade, try the capable model at a lower effort setting. Measure it on the same tasks first. It can match a cheaper model's cost with less complexity.
  • Prompt caches are per model. A cascade splits traffic across models, so it gives up cache reuse between them. This calculator ignores caching, so check that effect before trusting a saving.
  • The check is the cascade. Its catch rate sets your accuracy, and its false escalations set your cost. Measure both on labelled examples before you ship.
  • A router pays on every task. It wins when hard tasks are rare and easy to spot. Every hard task it sends to the small model costs accuracy.
  • Escalation adds latency. Escalated tasks wait for two calls in a row, so look at the slow cases, not only the average.
  • Measure, then decide. The defaults here are placeholders. Run an eval with your own tasks, then put the real numbers in.
# A cascade: small model first, escalate when its self-check fails
import json
import anthropic

client = anthropic.Anthropic()

SCHEMA = {
    "type": "object",
    "properties": {
        "answer": {"type": "string"},
        "self_check": {"type": "string", "enum": ["pass", "fail"]},
    },
    "required": ["answer", "self_check"],
    "additionalProperties": False,
}

def ask(model: str, question: str) -> dict | None:
    resp = client.messages.create(
        model=model,
        max_tokens=4096,
        output_config={"effort": "low", "format": {"type": "json_schema", "schema": SCHEMA}},
        messages=[{"role": "user", "content": question}],
    )
    if resp.stop_reason == "refusal":
        return None
    return json.loads(next(b.text for b in resp.content if b.type == "text"))

def answer(question: str) -> str | None:
    prompt = question + "\n\nSet self_check to fail if you are not sure your answer is correct."
    first = ask("claude-haiku-5-5", prompt)
    if first and first["self_check"] == "pass":
        return first["answer"]
    second = ask("claude-opus-5-5", prompt)  # escalate
    return second["answer"] if second else None
