Lab 2 · Sampling

How the next word gets picked

The model only gives you a probability for every possible next token. The decoding settings decide which one you actually get. Run the same prompt under three settings and compare what comes out.

How sure the model was about each token: 70%+ 40–70% 15–40% under 15% Hover any generated token to see the alternatives it beat.

Average confidence is the model's own probability for the tokens that were picked. Diversity is the share of word pairs that are unique across samples. Loops counts repeated three-token phrases, a sign of getting stuck.

What each setting does

Temperature

Divides every score before they become probabilities. Below 1 the favourite gets stronger. Above 1 the long tail gets a real chance. At 0 the model always takes its top choice, which is called greedy decoding.

Top-k

Keeps only the k most likely tokens and throws the rest away. It is a fixed-size safety net against very unlikely picks. Set it to 0 here to turn it off.

Top-p

Keeps the smallest set of tokens whose probabilities add up to p. The set shrinks when the model is confident and grows when it is unsure, so it adapts better than top-k.

Repetition penalty

Lowers the score of tokens that already appeared. Greedy decoding on small models loops easily; try a penalty of 1.3 on the greedy column and watch the loops count fall.

Starting points by task

TaskSetting to start fromWhy
Extraction, classification, code editsGreedy, or temperature 0 to 0.3You want the single most likely answer every time.
Chat assistantTemperature 0.5 to 0.8, top-p 0.9Natural variety without drifting into nonsense.
Brainstorming and creative writingTemperature 0.9 to 1.2, top-p 0.95More surprising options, so review the output.
Hard reasoning questionsModerate temperature, 5 to 10 samples, majority voteIndependent samples cancel out one-off mistakes. This is called self-consistency.
Testing a promptProduction settings, several runs per test caseOne sample hides how much the output varies.

Engineering takeaways

  • Change one knob at a time. Temperature and top-p both widen or narrow the choice, so tuning both at once makes results hard to reason about.
  • Greedy is close to repeatable, not guaranteed. Hosted APIs can still vary slightly between identical calls because of batching and floating-point effects. Design for that.
  • Low-confidence tokens are where the model guesses. A name, date or number picked at 10% is a hallucination risk. Some APIs return per-token log probabilities that you can use to flag shaky answers for review.
  • On current Claude models, steer with the prompt, not the sampler. Use examples, structured outputs and effort instead of temperature.
  • Sampling is a feature for evaluation. Running a prompt several times shows its spread, and majority voting turns that spread into accuracy.
# Self-consistency: ask several times, keep the most common answer
from collections import Counter
from anthropic import Anthropic

client = Anthropic()

def answer(question: str) -> str | None:
    resp = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=16000,
        output_config={"effort": "low"},
        messages=[{"role": "user", "content": question + "\nReply with only the final answer."}],
    )
    if resp.stop_reason == "refusal":
        return None
    return next(b.text for b in resp.content if b.type == "text").strip()

votes = Counter(answer("A bat and a ball cost £1.10 in total. The bat costs £1 more than the ball. How much is the ball?") for _ in range(5))
print(votes.most_common(1))
