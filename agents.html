Lab 6 · Agents and tools

An agent is a loop you write

Tool use looks like the model acting in the world, but the model only ever writes text. It writes a structured request to call a tool; your code decides whether to run it, runs it, and sends the result back. Repeat until the model says it is done. Step through three scenarios to see exactly what crosses the wire.

Input tokens sent per API call

Estimated at 4 characters per token, including the full tool schemas. Each call carries everything before it.

The request your code sends on the next call

Before you build one: should this be an agent?

An agent lets the model choose its own steps. That is powerful and expensive. A single call, or a fixed workflow where your code decides the steps, is simpler to test and cheaper to run. Reach for an agent only when all four of these hold.

Complexity

The task is multi-step and hard to specify in advance, such as turning a design document into a pull request.

Value

The outcome justifies more calls, more tokens and more latency.

Viability

The model is actually good at this kind of task. Check with a small evaluation first.

Cost of error

Mistakes can be caught and undone, through tests, review or rollback.

Engineering takeaways

  • Your code is in charge. The model proposes a call; your code validates the input, decides whether to run it, and owns the side effects.
  • Tool definitions are prompt. Names, descriptions and schemas are sent on every call and cost tokens every time. They are also your main lever on tool-use quality, so write them like documentation for a new colleague.
  • Return errors, don't crash. Send failures back as a tool result with is_error set, so the model can correct itself. When several tools run at once, send all their results back in one message.
  • Gate anything with side effects. Sending email, paying, deleting or deploying should pass a human or policy check first.
  • Bound the loop. Cap the number of iterations, log every step, and stop on any stop reason other than a tool call.
  • Mind the growing context. Every call resends the whole history, so cache the stable prefix and trim large tool results. The Context & cost lab shows the effect.
import json
import anthropic

client = anthropic.Anthropic()

tools = [{
    "name": "get_weather",
    "description": "Get the weather forecast for a city on a given day.",
    "input_schema": {
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "City name, for example London"},
            "date": {"type": "string", "description": "An ISO date or 'tomorrow'"},
        },
        "required": ["city", "date"],
    },
}]

def run_tool(name: str, args: dict) -> str:
    if name == "get_weather":
        return json.dumps(get_weather(**args))  # your implementation
    raise ValueError(f"Unknown tool: {name}")

messages = [{"role": "user", "content": "I'm in London tomorrow. Do I need an umbrella?"}]

for _ in range(10):  # never loop forever
    response = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=16000,
        system="You are a helpful travel assistant.",
        tools=tools,
        messages=messages,
    )
    messages.append({"role": "assistant", "content": response.content})
    if response.stop_reason != "tool_use":  # end_turn, refusal, max_tokens
        break

    results = []
    for block in response.content:
        if block.type == "tool_use":
            try:
                output, failed = run_tool(block.name, block.input), False
            except Exception as exc:
                output, failed = f"Error: {exc}", True
            results.append({"type": "tool_result", "tool_use_id": block.id,
                            "content": output, "is_error": failed})
    messages.append({"role": "user", "content": results})  # all results in one message

if response.stop_reason == "end_turn":
    print(next(b.text for b in response.content if b.type == "text"))
# The SDK's tool runner (beta) writes the loop for you
import anthropic
from anthropic import beta_tool

client = anthropic.Anthropic()

@beta_tool
def get_weather(city: str, date: str) -> str:
    """Get the weather forecast for a city on a given day.

    Args:
        city: City name, for example London.
        date: An ISO date or 'tomorrow'.
    """
    return "Rain likely, 80% chance, 14°C"  # your implementation

runner = client.beta.messages.tool_runner(
    model="claude-opus-5-5",
    max_tokens=16000,
    tools=[get_weather],
    messages=[{"role": "user", "content": "I'm in London tomorrow. Do I need an umbrella?"}],
)
for message in runner:  # one message per loop iteration
    print(message.stop_reason)
