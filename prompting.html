A prompt is just the start of a text

A language model continues text. Instructions, examples and chat roles all work by changing which continuation is most likely. This lab measures that directly, using GPT-2's real next-token probabilities on a small labelled test set.

What to look for. With no examples, almost none of the probability goes to either label, because the model has not learned the answer format. Balanced examples teach the format and improve accuracy. Examples that are all positive teach the model to say positive. Calibration divides out the model's bias measured on a blank input, which can rescue a biased prompt.

Constrained decoding: only allow valid answers

Left alone, the model can continue with anything, including text your code cannot parse. Constrained decoding scores only the answers you allow. Labels made of several tokens are scored by multiplying the probability of each token in turn.

Constrained to your answers

Structured outputs, enums in JSON schemas, and strict tool inputs use the same idea: the decoder is stopped from producing anything that breaks the format.

Roles are text too, and so is everything you paste in

A chat API takes separate system, user and assistant messages, but the model receives them as one sequence of tokens with role markers in between. The markers below are illustrative; every provider uses its own. The important point is that a document you paste in sits in the same stream as your instructions.

The red sentence is a prompt injection: instructions hidden inside data. Tags and a clear instruction help the model tell data from instructions, but they are not a security boundary. Never give a model access, tools or secrets that the least trusted text in its context should not control.

Engineering takeaways

  • Examples teach format faster than instructions. A few input and output pairs pin down exactly what you want back.
  • Balance and vary your examples. The model copies their label mix and their order. Lopsided examples produce lopsided answers.
  • Judge a prompt on a test set, never on one example. This page is a tiny evaluation. Real ones need dozens to hundreds of labelled cases.
  • Use structured outputs when code reads the answer. It guarantees valid JSON, so you are not parsing free text. On recent Claude models, the old trick of prefilling the assistant's reply returns an error, so structured outputs are the way.
  • Treat pasted and retrieved text as data. Delimit it, keep your instructions in the system prompt, and limit what tools can do.
# Guaranteed-valid label with structured outputs
import json
from anthropic import Anthropic

client = Anthropic()
resp = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=4096,
    output_config={
        "effort": "low",
        "format": {
            "type": "json_schema",
            "schema": {
                "type": "object",
                "properties": {"sentiment": {"type": "string", "enum": ["positive", "negative", "mixed"]}},
                "required": ["sentiment"],
                "additionalProperties": False,
            },
        },
    },
    system="Classify the sentiment of the customer review inside the review tags.",
    messages=[{"role": "user", "content": "<review>Terrible service and cold food.</review>"}],
)
if resp.stop_reason != "refusal":
    text = next(b.text for b in resp.content if b.type == "text")
    print(json.loads(text)["sentiment"])
