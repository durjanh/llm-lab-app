Models read tokens, not words

Before a model sees your prompt, a tokenizer chops it into pieces from a fixed vocabulary. Tokens are what you pay for, what fills the context window, and the reason models are oddly bad at spelling and arithmetic.

English prose usually runs at about 4 characters per token. Code, numbers, rare words and non-English text use more tokens for the same length, so they cost more and fill the context faster. The � blocks are pieces of a character that needs several bytes, such as an emoji or a Japanese character.

Why models trip up on some tasks

The model never sees letters or digits one by one. It sees the chunks below. That is why counting the letters in a word, reversing a string, or adding long numbers is hard without a tool.

Engineering takeaways

  • Every model family has its own tokenizer. This page shows GPT-2's, so treat its counts as a guide to the patterns, not to your bill. For Claude, count with the API's count_tokens endpoint. Don't use OpenAI's tiktoken; it undercounts Claude tokens, especially on code and non-English text.
  • Output tokens cost more than input tokens. On current Claude models, output is 5 times the input price. Asking for a shorter answer is often the cheapest optimisation there is.
  • Pick compact formats for bulk data. Minified JSON or CSV can carry the same records for far fewer tokens than pretty-printed JSON. Measure, because the model also needs the structure to stay readable.
  • Hand character-level work to code. Counting, exact string manipulation and long arithmetic belong in a tool call, not in the model's head.
  • Watch whitespace in templates. A trailing space or an extra newline changes the tokens the model sees, and can change its answer.
  • Budget the whole window. Reserve output room with max_tokens, and check your model's limit. For Claude, the Models API reports it as max_input_tokens.
# Count tokens exactly as Claude will see them
from anthropic import Anthropic

client = Anthropic()
resp = client.messages.count_tokens(
    model="claude-opus-5-5",
    messages=[{"role": "user", "content": open("prompt.txt").read()}],
)
print(resp.input_tokens)
