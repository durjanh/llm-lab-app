Search by meaning, then answer from your own documents

An embedding model turns a piece of text into a list of numbers, so that texts with similar meaning end up close together. That is the engine behind semantic search and retrieval-augmented generation (RAG): find the relevant passages first, then give only those to the LLM.

Retrieval-augmented generation, step by step

Below is a made-up company handbook. It is split into chunks, every chunk is embedded once, and each question is matched against them. The best chunks are pasted into the prompt for the LLM. Change the chunking and watch which passages get retrieved.

There are two ways to find candidates. Meaning search compares embeddings, so it matches vacation with annual leave. Keyword search, here the classic BM25 formula, scores chunks by the words they share with the question and gives rare words more weight. It finds exact amounts, codes and names that embeddings blur. Hybrid search runs both and merges the two rankings.

Try this: ask "Can I work from Spain for a month?" with fixed-size chunks, then switch to chunking by section heading. Then ask about the World Cup and watch the threshold stop an off-topic question.

Then compare methods: ask "Is there a £35 limit?" with embeddings only. Meaning search puts the travel section first, because an amount carries little meaning. Switch to keywords or hybrid and the expenses chunk that contains £35 wins. Now ask about vacation days with keywords only. The handbook says annual leave, never vacation, so keyword search grabs the wrong section.

Reranking the shortlist

A reranker is a second model that reads the question and one chunk together, then scores how well the chunk answers it. An embedding model reads them separately, so chunk vectors are computed once, ahead of time, and comparing them is cheap. A reranker must run once for every question and chunk pair. It is slower but more precise, which is why it only reorders a shortlist: here, the top 8 chunks that pass the rule above.

Engineering takeaways

  • Chunking decides what can be found. Chunks that are too small split an answer in half. Chunks that are too large dilute the match. Splitting on the document's own structure, such as headings, is a strong default, and some overlap protects answers that cross a boundary.
  • Test retrieval on its own. Write questions with known answer passages and measure how often the right passage appears in the top results. If retrieval misses, no prompt can fix the answer.
  • Use hybrid search. Embeddings handle synonyms, such as vacation and annual leave. Keyword search handles exact amounts, codes and names, such as £35 or extension 4400. Reciprocal rank fusion merges the two rankings by position, so you never have to compare scores that live on different scales.
  • Rerank a shortlist. A cross-encoder reads the question and each passage together, so it judges relevance more precisely than comparing vectors. It is too slow to run over a whole collection. Retrieve a few dozen candidates cheaply, then rerank only those.
  • Set a threshold and allow "I don't know". Off-topic questions still get a "nearest" chunk. A minimum score, plus an instruction to say when the documents don't contain the answer, prevents confident nonsense. A fixed minimum suits cosine similarity. BM25 and fused scores have no fixed scale, so give them their own rule, such as requiring a shared keyword.
  • Keep sources attached. Store a source id with every chunk so answers can cite it and users can check it.
  • Vectors only compare within one model. If you change embedding models, re-embed everything.
# Answer from retrieved chunks, with citations and an explicit way out
from anthropic import Anthropic

client = Anthropic()

def answer(question: str, chunks: list[dict]) -> str:
    docs = "\n".join(
        f'<document index="{i}" source="{c["source"]}">\n{c["text"]}\n</document>'
        for i, c in enumerate(chunks, 1)
    )
    resp = client.messages.create(
        model="claude-opus-5-5",
        max_tokens=16000,
        system="Answer using only the documents provided and cite document numbers. "
               "If the documents do not contain the answer, say you don't know.",
        messages=[{"role": "user", "content": f"<documents>\n{docs}\n</documents>\n\nQuestion: {question}"}],
    )
    if resp.stop_reason == "refusal":
        return "The request was declined."
    return next(b.text for b in resp.content if b.type == "text")
